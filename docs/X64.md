# x64 migration status

The production client, dedicated server, updater and SDK regression plugin now
build as native **AMD64 / PE32+** applications. The packaged native DX9 client
passed hosting Backlot, changing to Crash, fast restart, video restart, sound
restart, leaving the match and quitting. Each active stage checked advancing
rendering, prediction, snapshots and the simulation owner; quitting also stopped
the exact hosted server. This is scoped integration evidence, not complete
gameplay or performance acceptance.

Native production outputs are in `bin/x64/Release/`. The accepted root and
`runtime/` Win32 executables have not been replaced. Native packaging uses
`runtime/x64/`, plugins use `runtime/plugins/x64/`, and native updater manifests
use `windows-x64` with separate `updates/x64/` staging and rollback storage.

The native Vulkan client also loads and runs Backlot, but the matched view shows
black models/foliage and lower throughput. The same immutable packets also show
black models in the adapter's DX9 reference; the direct DX9 path renders those
models correctly. A 90-second native Vulkan session completed without a crash,
measuring 243.56 FPS and 1,000 Hz simulation in its fixed broad view. Vulkan visual
parity, broader gameplay tests and performance acceptance remain open. Moving to x64 has not
established full GPU utilization or more than 1,000 FPS in broad 1080p views.

## Build and test the converted components

Build and package the native game, then open its multiplayer menu with uncapped
DX9 rendering:

```powershell
./build.ps1 -Architecture x64 -Configuration Release
./launch-client.ps1 -Architecture x64 -Renderer d3d9 -RenderFps 0
```

The native build script fetches and verifies its pinned FFmpeg package before
configuration. The native executables can also be launched directly from
`runtime/x64/`; they locate the shared retail data in `runtime/`. The launch
scripts support `-Architecture x64` for the dedicated server and headless
benchmark client too. Use the regular client to measure rendered FPS.

For component verification without building the game:

```powershell
./build.ps1 -Architecture x64 -CoreOnly
./scripts/build-vulkan-tools.ps1 -Architecture x64 -Validation -GpuTest
python ./scripts/compare_graphics_fixtures.py ./results/vulkan-gpu-tools-x64
cmake -S cmake/engine-port-audit -B build/x64/native-engine-audit -G 'Visual Studio 17 2022' -A x64
cmake --build build/x64/native-engine-audit --config Release --parallel 8
```

Win32 remains the default for the existing build/deployment scripts. x64 core
outputs use `build/x64/<configuration>` and tools use
`runtime/tools/x64/<configuration>`. Native D3DX9 and validation libraries are
selected separately from Win32. The source audit compiles actual multiplayer
translation units into a static library with native layout assertions enabled;
that library is not an executable and does not prove runtime correctness.

The native audio/dependency audit also has standalone runtime fixtures:

```powershell
cmake -S cmake/engine-port-audit -B build/x64/native-openal-audit -G 'Visual Studio 17 2022' -A x64 -DKISAK_OPENAL=ON
cmake --build build/x64/native-openal-audit --config Release --parallel 8
ctest --test-dir build/x64/native-openal-audit -C Release --output-on-failure
```

`KHZ_BUILD_NATIVE_DEDICATED=ON` adds an experimental dedicated-server target to
this audit when OpenAL and x64 are selected. Its outputs stay under the audit
build directory, with no deployment commands or copies of the x86 dependency
DLLs. Backlot loaded cleanly in 45-second owned probes, including two active bots.
A separate `KHZ_BUILD_NATIVE_CLIENT=ON` target builds the graphics client with
OpenAL and a native FFmpeg cinematic adapter. It has run a stock Backlot match.
Run `scripts/prepare-native-video.ps1` first to fetch the pinned shared LGPL
dependency. Client outputs stay under `native-client/Release` in the audit tree.
These audit targets remain isolated integration builds. The normal root x64
engine configuration now builds the actual client/server with native OpenAL,
FFmpeg and D3DX9 dependencies; it does not link the x86 Miles/Bink/Steam imports.
For an explicit production build without packaging:

```powershell
./scripts/prepare-native-video.ps1
cmake -S . -B build/x64/engine-release -G 'Visual Studio 17 2022' -A x64 `
  -DCOD4X1KHZ_BUILD_ENGINE=ON -DCOD4X1KHZ_BUILD_VULKAN=ON
cmake --build build/x64/engine-release --config Release `
  --target KisakCOD-mp KisakCOD-dedi khz_regression cod4x1khz_update --parallel 8
```

The `khz_runtime` target packages this architecture into `runtime/x64/`.

## Implemented and checked

- **57 core suites** pass under both Win32 and x64. Scheduling and uncapped
  presentation policy retain their existing isolated tests. Native Backlot telemetry measured 1,000.02 Hz
  with two moving/aiming bots and zero accumulated tick debt over nine seconds;
  wider match, network-client and renderer acceptance remain outstanding.
- Retail records retain their original 32-bit disk representation. **150 asset
  schemas with 1,641 fields** convert into native structures through separately
  measured offsets. Production loader calls distinguish typed records, pointer
  slots and raw bytes; stream blocks, aliases, delayed fixups, temporary rewinds
  and geometry blocks have focused tests. Generated offsets are checked against
  both compiler ABIs. The isolated native server now loads the complete stock Backlot server
  fastfiles. The native graphics client loads stock Backlot client fastfiles.
- Hunk and pool allocators preserve native addresses, alignment and native
  headers. Tests allocate above 4 GiB, exercise reuse, exhaustion, commit/reset,
  temporary allocations and asset lists. Physical memory reserves 1 GiB lazily
  on x64, committing touched ranges; Win32 retains its original 128 MiB arena.
  DObj model arrays use pointer widths.
- Huffman sorting uses typed native pointers. All **243,976** comparisons retain
  fingerprint `31442bde5f36413f`, matching the original x86 encoder. Message
  runtime headers are checked at 40/48 bytes while transmitted bytes remain
  unchanged.
- SSE2 skinning replaces unavailable x64 MMX operations. Real rigid and weighted
  production functions match the original x86 fingerprint `46c1572ade84e639`
  across all tested MXCSR rounding modes.
- Script values preserve native code/vector/archive pointers. Stack archive
  entries use native widths; compiler, VM and debugger paths have corresponding
  changes. Production parser/compiler allocations use native structure sizes. Relative
  jumps and animation handles retain four-byte operands, while pointer fixups
  retain native addresses. Stock Backlot scripts and bot scripts run without
  errors. The embedded timing probe passed waits, notifications, frame-end
  rearming and the former 24-bit clock wrap.
- Usable-entity sorting uses complete native records instead of the old eight-byte
  stride, preserving full pointers and the original score comparison. Regression
  tests cover addresses above 4 GiB, full-record association and guard bytes.
- Settings-name lookups use a separate reader/writer lock from prediction-tick
  value ownership. Tests check recursive writer access, blocked metadata reads
  during registry writes, independent name reads during a tick and fair ownership.
- Dvar string and enum operations use their actual pointer members. Production
  ownership tests include two addresses with equal low 32 bits. UI tokens,
  expression entries, local variables and HUD sorting use native structure
  sizes and pointers, with production helper tests.
- Pure-server IWD names retain complete native pointers across map changes.
  Scoreboard lookup uses typed score records and bounded client/rank indices.
  Production fixtures cover repeated lists, replacement and all 64 score slots.
- Effects archives save native system/buffer sizes, native definition keys and
  relocation distances. The production archive fixture restores across an 8 GiB
  address gap, distinguishes definitions with equal low 32 bits, checks all
  1,024 effect handles and preserves the full buffer tail. Runtime video and
  sound restarts passed in the packaged client. Internal restart archives are
  local to their ABI; retail fastfile wire layouts retain their original sizes.
- Collision shutdown clears the entire native clip map, retiring unloaded map
  pointers before repeated disconnect/quit. Dynamic-entity allocations, sorting,
  physics IDs and archives use native records and pointers. Production shutdown,
  sort and archive fixtures pass on both ABIs.
- Worker queue descriptors copy actual command sizes. Packed static-model
  commands encode/decode complete native surface pointers, including odd/even
  index lists; hidden model records preserve native alignment. Enumeration
  callbacks use typed bounded containers. Native DX9 stock-scene rendering has been checked on Backlot. HUD icon tokens,
  text commands and command alignment retain full native pointers; actual command
  construction tests cover binary icon payloads and circular text-pool wrapping.
- Native plugin headers use SDK3/protocol 10002; Win32 remains SDK2. C and C++
  layout fixtures pass. The native dedicated server loaded the real AMD64 regression DLL, ran 1 ms
  frame/tick callbacks with zero gaps and applied a worker completion, then
  unloaded it and retired its script bindings without a crash. The checked
  lifecycle is recorded in `results/x64-native-plugin-lifecycle.json`; broader
  plugin networking/filesystem lifecycle acceptance remains outstanding.
- The OpenAL backend compiles as x64. Its runtime fixture checks mono/stereo PCM
  loading through both allocators, all 53 channels, gains, and two real device
  initialization/shutdown cycles. The fastfile path now decodes PCM8 and IMA-ADPCM into PCM16, with mono/stereo
  payload fixtures. Streaming, channel-map and EQ acceptance remain outstanding.
- Native cinematic playback uses FFmpeg through the existing Bink texture
  interfaces. A 299-frame stock fixture passed disk/memory parity above 4 GiB,
  pitched plane canaries, an independent Y/U/V reference, looping and pause
  timing. Bink audio decoding/queuing preserves the game's OpenAL context.
  Native client cinematic display and broader audio/video parity remain
  outstanding. The dependency is pinned to the shared LGPL FFmpeg 8.1 build
  `29e619e767` from [BtbN](https://github.com/BtbN/FFmpeg-Builds), using the retained
  September 2026 monthly build and a verified SHA-256.
- Native Steam imports bind to a real sibling `steam_api64.dll` using the SDK's
  version checks and callback exports. Missing/incompatible runtime failures
  preserve initialization failure and offline behavior; the missing-runtime
  fixture passes. Authentication with the actual native redistributable remains
  unverified. See [Valve's API documentation](https://partner.steamgames.com/doc/sdk/api).
- Native debugger probes use AMD64 registers; Win32 targets use WOW64. Console
  window callbacks use `SetWindowLongPtrA`. The real x64 Vulkan preflight selects
  the RX 9070 XT; **108** DX9/Vulkan fixture pairs have SSIM **1.0** and zero
  differing channels. Those fixtures do not establish retail-map visual parity
  or game performance.

## Remaining acceptance work

1. Extend native pointer/layout audits and runtime coverage, particularly
   object-mode animation construction, physics-heavy effects, renderer scratch
   storage and callbacks.
2. Finish full native dependency integration. Audio still needs retail parity;
   native cinematic integration needs visual/audio acceptance in the running client.
   Supplied Miles/Bink/Steam libraries and DLLs are x86. Production native builds
   select OpenAL/FFmpeg and the optional native Steam binding instead.
3. Extend native game acceptance beyond the checked Backlot/Crash lifecycle:
   exercise longer matches, more maps, loss recovery and native plugins. Validate
   authoritative 1 ms simulation and replay behavior.
4. Compare camera-matched DX9/Vulkan visuals and uncapped throughput on actual
   routes. Preserve the optional 1,000 FPS cap and 1 kHz simulation. Aggregate
   CPU utilization does not establish per-thread headroom; moving to x64 alone
   does not guarantee higher FPS or full GPU utilization.

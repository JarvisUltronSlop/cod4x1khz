## Address and transport seam

The public SDK2 address is 32 bytes: type, scope, port/pad, socket, and a16-byte IPv4/IPv6 union. The native engine still uses20 bytes (`engine/src/qcommon/net_chan_mp.h`). Native values5/6 mean obsolete IPX families, whereas the public pin uses5 for IPv6 and6 for TCP. Public `NA_BAD` and `NA_BOT` alias zero, unlike the engine. A reinterpret cast is incorrect even for IPv4 because the byte offsets differ.

SDK2 now has a public address header with the pinned source names/layout and a separately named host bridge type. It explicitly copies/translates native IPv4 fields and asserts every public field offset/size in C and C++ smoke fixtures. The marker revision is2; older markers are rejected before callbacks. Native bot/bad distinction remains internal. `OnPlayerConnect`, `OnPlayerWantReservedSlot`, all three IP-ban exports and the embedded public HTTP `remote` field migrate together. Connection callbacks receive a shared copied address and preserve mutable denial/userinfo/reserved flags; address field mutations do not retarget the native endpoint whose proof was already validated. Native20 IPv4 endpoints remain in core transport. The current parser's socket0 is not proof that a configured IPv6 socket exists.

For complete IPv6 server semantics, the native transport must retain IPv6 endpoints through reception, owner packet queues, challenge/proof records, netchan/client addresses, replies, fake-lag queues, and checkpoint images. Prefer an explicit custom-MP native address extension and translation rather than a synthetic IPv4 token for IPv6: tokens would corrupt base-address comparison, bans, RCON limits, identity endpoint binding, and address reporting. Changing the native address requires auditing typed assignments plus decompiled fixed-size/field writes; enlarging a struct alone is insufficient. SP and editor definitions remain their existing separate targets.

`engine/src/win32/win_net.cpp:258` currently receives only IPv4/IPX-sized sockaddrs. `Sys_SendPacket:394` chooses the static IPv4 `ip_socket`; its absent-socket path currently reports success. Extend the actual engine socket owner with IPv6 bind/receive/send and a nonblocking, lifetime-checked native send helper that reports the real byte/result. Both families must use the configured server port/interface. An independent ephemeral SDK socket would violate the public source-port behavior. IPv6 multicast/broadcast policy requires the matching explicit family socket and configured enable flags.

Publish a bounded copied interface/mask catalog outside ticks. Formatting/comparison/numeric parsing and catalog reads allocate nothing and perform no DNS or interface enumeration. Hostname resolution runs only in a pinned SDK job/thread, with a real bounded DNS deadline; numeric or cached queries may run on the owner. Document this rebuild-time ownership requirement. Preserve explicit-port return semantics and test port values above 32767. Reject malformed/overlong input before resolver work; any deliberate stricter syntax than the pinned `atoi` conversion must be documented and covered.

## Owner callbacks and injection

Insert server receive callbacks before `SV_PacketEvent` at the real owner drain (`engine/src/qcommon/common.cpp:1014`). Insert send callbacks before the server's native/loopback send at `engine/src/qcommon/net_chan_mp.cpp:1156`. Supply bounded copied public addresses, bytes and a local veto flag; copy permitted address/data mutations back only after validating type, size, family, scope, and lifecycle. Preserve synchronous veto semantics. Do not invoke gameplay/plugin callbacks on the private client prediction owner or an I/O worker. Declare the native server-owner send requirement where synchronous veto prevents an equivalent worker implementation.

`Plugin_ServerPacketEvent` now uses a16-slot copied mailbox, at most65,507 bytes per packet. All callers, including owner/tick callbacks, defer to outer service (eight dispatches per pass); this deliberately prevents connect/map handlers running inside gameplay simulation. The mailbox preserves reservation and per-producer order without spinning on the owner. Module generation, server session, serverId and lifecycle epoch are rechecked before native dispatch. No DLL/stack pointers survive. Injection bypasses the physical receive callback, matching the pin; protocol/proof validation remains native. Full-server checkpoint support is still staged: its observer must exclude loaded plugins/pinned jobs and pending network work, or implement actual external-effect rejection before admitting replay. These networking changes do not establish full-world rewind eligibility.

Existing `IpBanCache`, administration subjects and RCON keys remain IPv4-only (`khz_admin.h:26`, `125`; `khz_admin_server.cpp:107`, `527`, `703`). Replace transient network keys with exact tagged IPv4/IPv6 bytes; retain the public 32-entry bound and real-seconds expiries. The pinned ban cache stores a full address and uses base comparison, so truncating IPv6 to a 32-bit hash or zero is incorrect. SDK2 rejects unsupported IPv6 ban calls without truncation and corrects the public IPv4 `Plugin_PlayerBannedByip` formatting to return reason plus remaining-time message and regard <=1 second as expired. Persistent policy format migration requires a versioned backup/read path if its stored IP schema changes; this checkpoint does not alter that schema.

## New isolated component

The address component is `engine/src/khz/khz_plugin_net_address.h/.cpp`, with `sdk/include/public_net_address.h` and12 exact declarations in `public_net_api.h`. `khz_plugin_net.inl` supplies the public wrappers. Explicit field copies reject IPX/IPv6 truncation. `khz_plugin_dns.{h,cpp}` owns actual GetAddrInfoExW operations: four per module,64 total, a five-second absolute deadline, generation cancellation and retained unfinished OVERLAPPED storage. It resolves without contacting a TCP endpoint. Numeric parsing and interface catalog reads remain allocation-free. Hostname calls require a pinned worker and return only actual completion; main calls fail0 with cleared output. IPv4 results carry the current configured communication socket. Windows interface capture remains off-tick with fixed64KiB scratch and64 entries.

`KHZ_NativeUdpSend` in `win32/win_net.cpp` uses the actual configured `ip_socket`, reports kernel failure/would-block honestly and keeps worker SOCKS staging private. A shared fence protects sends against native close/reuse; published socket/relay assignments occur only outside fallible engine calls, so longjmp cannot strand the fence. Normal server sends invoke `OnUdpNetSend`; direct `Plugin_UdpSendData` bypasses it. Physical owner reception invokes `OnUdpNetEvent`; private client-owner traffic never enters DLL code. Callback address/payload edits and vetoes are synchronous, with four-level reentrancy limits and reported callback overruns. Blocking/registration APIs and synchronous logging are excluded from these fast network callbacks.

`scripts/plugin_udp_native_probe.py` is the prepared35-second owned native fixture for configured source port, direct and pinned-worker sends, actual hostname families/default ports, receive/send byte and endpoint edits, vetoed real delivery, copied injection, invalid protocol/proof rejection and cancelled generation cleanup. Standalone DNS and mailbox fixtures additionally cover bounded concurrency, per-producer order, retained provider lifetime and absolute deadlines. Fixture sources alone do not count as semantic proof.

Standalone proof sources are `engine/tests/khz_plugin_net_address_tests.cpp` and the separately compiled C `khz_public_net_address_smoke.c`. They check independently specified address bytes, the native Winsock parser, pinned type/mask/format conventions, sentinel-protected buffer bounds, family translation, real sockaddr conversions and copied local-interface mask membership. The original standalone component and coordinator tests passed at `results/checkpoint-address-build/tests.log`; the later off-tick interface capture and SDK2 host integration await build63/native proof. The target needs both test files and the component `.cpp`, include paths `sdk/include`/`engine/src`, plus `ws2_32` and `iphlpapi`. Production transport still uses native20 IPv4. The real rebuilt DLL cases are in `sdk/tests/native_net_address_probe.inc`; `scripts/plugin_net_native_probe.py` is prepared for an owned35-second numeric/admission/transient-ban fixture, with actual binary/source hashes and cleanup.

Deliberate bounded adapter differences requiring documentation: strict numeric ports 0..65535, numeric Windows scopes 0..INT32_MAX, rejected malformed brackets/overlong input before DNS, and an empty output for unsupported formatter types instead of the pinned formatter's stale buffer contents. Public zero aliases bot/bad; conversion back into the old native address treats that ambiguous value as native bad, so it cannot create a native bot admission. Final generic IPv6 game/UDP support still requires the complete native transport migration described above.

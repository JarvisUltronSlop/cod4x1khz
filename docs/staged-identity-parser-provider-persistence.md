## Parser boundary

Keep the existing `Plugin_StringToSteamID` signature and twenty-command fixture budget. Add `khz_fixture_identity parse` to the existing dispatcher only after the implementation is reviewed. Production parsing remains in `khz_identity.cpp::StringToSteamId`; its current `number` helper rejects valid field-leading whitespace/plus accepted by the pinned `%hu`/`%u` conversions. Do not change the general helper used by unrelated protocols.

Pinned source is `upstream/cod4x_server/src/sapi.c`: account-type aliases at 36, Steam3 parsing at 67, legacy parsing at 139, decimal parsing at 200, and ordered legacy/Steam3/decimal dispatch at 278. `src/qshared.c::isInteger` at 1622 can incorrectly accept a numeric prefix before a space/newline and permits a minus sign; those behaviors are error-handling defects, not valid positive identifier forms to preserve.

The narrow parser patch should use a private bounded unsigned field reader. It permits the six ASCII whitespace characters before each legacy/Steam3 numeric field and one optional leading `+`, requires at least one decimal digit, rejects every negative, and checks overflow before multiplying. Separators must immediately follow digits; whitespace before a colon remains invalid. Retain the existing outer ASCII-space trimming. Decimal Steam64 accepts digits after that outer trim, with no plus, minus, bracket or trailing junk. Reject original inputs of 128 or more bytes before any trim or truncation; a long input may not become an accepted prefix. These deliberate input-size, overflow, negative and junk refusals are recorded safety corrections.

Preserve exact legacy `STEAM_` case, instance 0/1, low bit 0/1, and high part at most `UINT32_MAX/2`. The latter two bounds prevent pinned unchecked shift/OR artifacts. Preserve the eleven Steam3 spellings `U M G A P C g T c L a`, with `T/c/L` mapping to type8, allowed universes1–4/32–39, account0–`UINT32_MAX`, default instance1 for U/G and0 otherwise. Balanced optional brackets apply only to Steam3. Four-field Steam3 with instance0–`0xfffff` is the explicit conversion-count bug correction: the pinned source first accepts four conversions, then erroneously requires three. Keep that documented correction and remove the current undocumented bracketed-decimal extension. Do not infer authentication from a parsed ID.

The staged contract data carries independently assembled bit-layout expectations and labels pinned-valid, safety correction, bug correction, or rejected extension separately. Before integration, expand it into native C cases for all type aliases, every universe byte, account/instance limits, leading-whitespace/plus positions, colon/bracket shapes, null input, 127/128-byte boundaries, and terminated-prefix behavior. Compare actual exported return values and guard bytes. The native fixture must identify each failing case, report per-class counts, and reject missing/duplicate markers. Classifier and formatter coverage remains separate.

It is not an SDK export, public failure dvar, or a global CNG interception. Reject nested diagnostic entry; the context is removed by RAII before returning.

Execute the actual `GuidToPlayerId` with (1) the normal real provider, (2) an open failure before provider creation, (3) a derive failure after a real successful open, and (4) the normal real provider again. Verify exact independently reviewed golden results before/after, zero failure returns, open/derive/close counts, zero surviving owned handles, and a cleared injection context. Also execute actual SHA256 and P256 key/sign/verify calls within the GUID failure scope, with no interception counts, to prove isolation from those unrelated production paths. Clean all temporary key material and never persist a diagnostic key.

An archive-bound harness calls it outside server ticks and then the loaded DLL's existing `guid` command to reconfirm the public export's 247 normal/null/malformed cases. This claims the GUID wrapper's documented zero-on-local-provider-failure adaptation and resource cleanup only. It does not claim an actual Windows provider outage, official account identity, or all cryptographic error paths.

`khz_admin_server.cpp::KHZ_AdminInit` at405 registers `sv_usesteam64id` default true with `DVAR_ARCHIVE`. `common.cpp::Com_WriteConfig_f` at1735 invokes `Com_WriteConfigToFile` at1754, which writes through `FS_FOpenFileWriteToDir(...,"players")` and `Dvar_WriteVariables`. `universal/dvar.cpp::Dvar_WriteSingleVariable` at121 writes archived latched values as `seta`. `cmd.cpp::Cmd_Exec_f` at1432/`Cmd_ExecFromDisk` and the native FS players search path provide the configuration reload route.

Use two fresh, ordinary project benchmark server homes and three serial processes. First home/process: verify default1 through the loaded DLL formatter, unload and quit normally. Second fresh home/process: supply startup `+set sv_usesteam64id 0`, verify initial0/restored0, then run native `writeconfig khz_identity_saved.cfg`, unload and quit normally. Capture its hash and preserve the file exactly. Do not write a replacement configuration from Python.

Third process: restart on the second home's same owned port without `+set sv_usesteam64id`. Execute the exact saved configuration through native `+exec khz_identity_saved.cfg` before the plugin/map startup sequence. The existing loaded-DLL formatter must observe initial0 and restore0; the saved file bytes must remain unchanged. This proves actual native save/reload persistence through the dedicated server's explicit config route. Dedicated bootstrap does not create/select a player profile (`khz_paths.cpp` excludes that section under DEDICATED), so this is not a claim of automatic client-profile loading. A separate client profile acceptance case is needed if that behavior is included in the dvar capability's complete contract.

Bound all three processes and their exact normal cleanup to thirty seconds, serial with no other games or services. Reuse strict project/reparse/fresh-home enrollment from the newer identity harness rather than the older formatter harness's runtime-relative check. Preserve owned PID, exit code, phase commands/replies, file bytes/hashes, actual server/DLL/source/archive hashes, default/configured/restarted values, unload result and all cleanup failures. A failed save, incomplete reload, manual `+set` override on the restart phase, missing provider marker, or forced cleanup remains a failed or partial record.

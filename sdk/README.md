# cod4x1khz rebuilt plugin SDK

This SDK adapts the public CoD4x names and source-level interfaces inspected at server revision `ddd65fc`. Build Win32 plugins with the default MSVC `/Gd` C calling convention against `sdk/include/pinc.h` and the generated dedicated server import library. A rebuilt DLL contains the marker for custom protocol **10002**, SDK revision **2**; the host rejects older markers before invoking lifecycle callbacks. Rebuild host, backend and DLLs together: SDK2 changes public address layout, including the embedded HTTP request remote address. Upstream copyright/license notices remain under `upstream/cod4x_server` and the project third-party notices.

The C header exposes opaque native client/entity/player-state/dvar pointers and adapted command/entity-reference types. Its public `netadr_t` has the pinned 32-byte address representation, with IPv6, scope, socket and unsigned network-order port fields. The engine still keeps native 20-byte IPv4 endpoints: explicit field copies translate connection/reserved-slot callbacks and IPv4 ban APIs. Never cast between them. Connection callbacks receive a shared copied public address; its field mutations do not retarget the native endpoint whose custom identity proof has already been validated. Denial, userinfo and reserved-slot flags retain their existing mutable callback semantics. C++ plugins needing gameplay structure fields must include matching project engine headers and define `KHZ_PLUGIN_NATIVE_TYPES` before `pinc.h`; their public address parameters use `khz_public_netadr_t` explicitly, distinct from native `netadr_t`. Stock gameplay structure layouts and unchanged DLL binary compatibility are outside this SDK contract.

`OnInit`, `OnInfoRequest`, and the existing event names keep their public semantics. `OnFrame()` executes once per **authoritative millisecond**, alongside `OnTick(uint64_t tick, double milliseconds)` where milliseconds is always `1.0`. Use seconds or millisecond deadlines for rates; a frame counter now counts 1,000 frames per second. `OnOneSecond` and `OnTenSeconds` use absolute real-time deadlines in outer service, coalesce missed periods after a stall, and do not replay a burst of maintenance callbacks.

Commands and GSC functions/methods are bounded and attributed to their registering DLL. Compiled scripts call stable host thunks, so a cached function cannot jump into an unloaded DLL. Retired script slots are reclaimed only after a verified VM shutdown barrier. Disable/unload makes those bindings unavailable immediately. Import pins and asynchronous job pins defer DLL unloading; a consumer's imports are released after its callbacks and jobs finish. Plugins remain trusted native code and must cooperate with their lifecycle.

Preallocate using `Plugin_Malloc` during initialization (50 tracked allocations per plugin, maximum 16 MiB per allocation). Registration, allocation/free, string dvar changes and DLL operations are rejected during authoritative gameplay work. `Plugin_Print*` prints main/control calls synchronously so native RCON redirects receive their output; authoritative callbacks and workers use bounded journals that outer service drains. Warning/error retain their public colored prefixes. `Plugin_Cbuf_AddText` queues work for the owner. Numeric dvar updates, scripts and engine pointer APIs remain authoritative-owner operations. Thread-safe dvar getters copy/read under the engine's dvar synchronization scope; returned text is copied into the caller's buffer while that scope is held.

`Plugin_QueueJob(work, argument, completion)` accepts up to eight pending/running jobs per plugin using preallocated descriptors. Work executes off the authoritative owner and may use the bounded private HTTP, file and TCP adapters. Work must not retain or touch mutable engine pointers, call GSC, or invoke owner-only APIs. Completion runs in outer service. The module remains pinned until completion is drained. Stop submitting work when shutting down; `OnTerminate` must ask plugin-created work to finish. No worker is forcefully terminated while it may hold locks or execute DLL code.

Callback duration, overruns, rejected APIs/jobs, and dropped journal records are reported through `KHZ_PluginStatsJSON`. Arbitrary plugin computation can exceed a millisecond, so 1 kHz acceptance must be measured with the actual enabled plugins. Blocking maintenance on the main server owner also delays its next tick; move such work into asynchronous jobs.

`Plugin_G_LogPrintf` uses the native map's `g_log` file and captures its timestamp before service delay. `g_logTimeStampInSeconds=1` selects Unix UTC seconds; the default retains game minutes/seconds. Its bounded journal flushes outside ticks and before the native file closes, and invalidates records at error/map barriers. `Plugin_PrintAdministrativeLog` targets project `administration/audit.log`, capturing Unix time and the current invoker's key/name/power plus plugin name immediately. These two destination-specific APIs are owner-only; asynchronous jobs may use the separate thread-safe console journal.

`Plugin_BanClient` retains the original subject and admission generation in a typed bounded request. It persists the copied identity in outer service and disconnects only that admission if still connected. Trusted plugins have the public privileged ban capability; the integer invoker UID is retained for attribution and never interpreted as a replacement identity. Duration `-1` is permanent, positive values are minutes bounded to 30 days, and zero disconnects without retaining an already expired ban. Explicit IP-only ban APIs retain their distinct transient cache; a keyed ban does not automatically ban unrelated keys sharing an IP.

`Plugin_AddCommandForClientToWhitelist` grants a named registered command to one proven human admission, with 32 entries matching the public bound. Admission reset clears entries. Player requests and plugin callbacks recheck the live server command rule and actual native command presence; a registration-time power is not a lasting authorization. Whitelist access bypasses the command entry minimum, while administration's target hierarchy and mutation checks remain active.

`sdk/tests/regression_plugin.c` is a real C DLL fixture for registration, usercall, callbacks, unload and a ten-millisecond asynchronous job. `sdk/tests/plugin_fixture.gsc` exercises actual dynamically resolved native functions/methods. The pure registry CTest separately verifies limits, callback/import pins, duplicate guards, stable retired slots and deadline arithmetic. Fixture existence is not runtime verification.

The existing project IWD packaging script includes `scripts/khz_plugin_fixture.gsc`. Start a dedicated test with `+set khz_plugin_tests 1 +loadPlugin khz_regression +map mp_killhouse`, preserving that order so the DLL's bindings exist before script compilation. Map startup executes the gated GSC fixture after the gametype startup and before bot bootstrap. It checks the dynamic global function and global usercall immediately, then waits for a player connection to check the entity method and entity usercall. Confirm both `KHZ_PLUGIN_SCRIPT_FIXTURE` success records, invoke `khz_fixture_report` for actual tick/job counters, and test unload separately. The flag defaults off.

Implemented exports are recorded in `docs/public-plugin-coverage.json`. New private file/ZIP and numbered TCP adapters require their native DLL semantic fixtures before any parity claim; generic NET/address/UDP and producer-less callback capabilities remain pending. Identity conversions are pure conversions; the custom proof identity and Steam-provider-unavailable responses do not imply authentication by official services.

SDK2 adds bounded public address comparison/formatting/classification and numeric IPv4/IPv6 parsing. Explicit/default ports return1/2; numeric scopes and unsigned ports are preserved. Build64 source adds actual hostname resolution only inside pinned jobs/threads, with four operations per module and a five-second absolute deadline. Owner hostname calls fail0 and clear output. Numeric parsing remains tick-safe. IPv4 parsed/resolved addresses carry the configured native UDP socket; IPv6/TCP values do not imply an available native server socket. LAN checks use the pinned prefixes plus an immutable actual interface-mask catalog captured outside ticks. Non-MT formatting buffers are thread-local.

`Plugin_UdpSendData` uses the actual configured native IPv4 socket and returns real nonblocking kernel success, including its existing source port. It bypasses `OnUdpNetSend`, matching the public pin. Normal native server sends and physical receives invoke their respective mutable/veto callbacks on main; private client-owner traffic never executes DLL code. Fast network callbacks use bounded logging and reject blocking/registration APIs. `Plugin_ServerPacketEvent` copies bytes/address into a16-packet mailbox, then validates module generation/session/serverId at outer-service dispatch. This deliberate adapted rule applies to owner callers too, keeping connect/map handlers outside gameplay ticks. Injection bypasses `OnUdpNetEvent` and retains real native protocol/proof validation. IPv6 UDP and IPv6 transient bans remain unsupported until the complete native endpoint/cache migration; formatting and TCP tests do not prove game transport parity. Run the owned `scripts/plugin_udp_native_probe.py` after a coherent deployment; its existence is not runtime verification.

Build63's real `khz_fixture_net`, `khz_fixture_net_ipban` and private-slot admission passed48 assertions, with scoped hashes/evidence in `docs/evidence/plugin-native-build63-address.json`. IPv4 banned-by-IP messages include the pinned reason/remaining-time text and consider <=1 second expired. Public IPv6 IP-ban calls are rejected without truncation or collision. Full public feature parity is still a separate release gate.

The optional owner command `khz_fixture_policy <proven human slot>` exercises whitelist addition/unknown-command denial and writes separate `KHZ_PLUGIN_GAME_LOG_FIXTURE` and `KHZ_PLUGIN_ADMIN_LOG_FIXTURE` markers after map startup. The public `Plugin_CanPlayerUseCommand` query reports whitelist membership; dispatch separately checks membership or current command power. Check `before=0 after=1`, execute the granted report command through the real player adapter, and confirm reset after reconnect. Use isolated policy/key storage for destructive ban fixtures. Pure policy/journal fixtures check copied identities, same-key slot generations, live powers, 32-entry limits, minute/appeal boundaries and file-handle reuse; they do not replace native proof.

`khz_fixture_stats <isolated proven human slot>` exercises native SDK stat reads/writes at byte fields0/1999 and long fields2000/2301/3497, rejects invalid boundaries and byte256, and restores every original value before reporting. These APIs require all native stat packets (`statPacketsReceived=127`); failure to roundtrip also detects an incomplete handshake. After reliable stat updates settle, compare the client profile's combat/rank buffer hash before and after. `khz_fixture_identity` checks real exported GUID/Steam conversions against independent golden values and rejects malformed identifiers. Conversion success does not establish official-provider authentication.

The public callback thread APIs copy exactly eight pointer arguments and retain at most eight workers per module. Raw workers and callback workers carry the module's admission generation in TLS. `Plugin_SetupThreadCallback` queues one owner completion after its worker exits; a disabled/unloaded generation receives no callback. The host pins the DLL until Windows confirms the wrapper has exited. `Plugin_ExitThread` raises a private structured exit caught by the host worker wrapper; a plugin must not catch and suppress that exit. It releases any host plugin critical-section depth and preserves completion bookkeeping. As with the pinned OS thread-exit behavior, arbitrary plugin C++ destructors are not guaranteed; return normally when plugin-local RAII must run. No C++ exception crosses the exported C ABI. Main-owner critical sections and sleeps are rejected; synchronize plugin-private work off-thread and publish owner changes through completions. Native engine pointers, script calls and command execution remain unavailable to workers. Faults such as access violations, arbitrary process termination or unmanaged plugin threads are outside this cooperative contract.

Run `khz_fixture_threads_start`, allow service to drain, then `khz_fixture_threads_report`. Expected markers include `start=1 raw=1 worker_owner=1 arguments=1 setup=1 finished=1 callbacks=1 callback_owner=1 exit_unreachable=1 tick_rejected=1`. Repeat separately with unload requested while work is active to verify deferred DLL lifetime and suppressed stale completion. `khz_fixture_aliases` checks fresh version metadata, loaded/missing queries, client-pointer conversion, invoker context and the pinned deprecated UID/GUID/PunkBuster no-op results. The fatal error case intentionally terminates a process and needs its own isolated native fixture; warning/disable results do not prove it.

Public HTTP supports copied bounded HTTP/HTTPS requests through a private service worker. `MakeHttpRequest` enqueues; `SendReceiveData` returns zero while pending, one when the response is immutable, and minus one on error. `FreeObj` releases only the owning module/generation's request. Requests are cancelled when that generation disables or unloads. Blocking `Request`/`GET` are available only inside explicitly pinned plugin jobs or workers; they are rejected on the authoritative owner. Allocation and form appending remain outside authoritative ticks. Explicit configured headers, methods and bodies are retained; redirects do not forward credentials and non-idempotent requests are not retried automatically. Parsing preserves the public 32-field interface, decodes once, rejects malformed/NUL/overflow forms, and leaves repeated lookups stable. Use a request pointer only until `FreeObj`; a freed pointer is invalid.

`khz_fixture_http_forms` checks actual exported form functions plus owner blocking rejection. `khz_fixture_http_start <controlled URL>` submits a POST from a pinned job with `Authorization: fixture-token`, body `command=HELO&literal=A%2BB+%26%3D%2525`, and form content type. The controlled endpoint must validate those inputs and return HTTP200 with `status=okay&literal=A%2BB+%26%3D%2525`. After service, `khz_fixture_http_report` must show `active=0 worker_response=1 completions=1 owner=1`. Standalone HTTP service tests do not replace this DLL-to-native fixture, nor prove compatibility with official remote services.

The public filesystem APIs use copied native search descriptors and private Windows file handles/ZIP decoders. Blocking file operations, including opens, reads, writes, closes and classic ZIP password changes, require pinned jobs or plugin threads. Native engine handles are never shared. Normal writes target home/game; SV writes target home; explicit base writes remain beneath base. `ReadLine` retains the public 1/0/-1 semantics for SV loose reads. The adapted `Plugin_FS_GetZipHandle` exposes an owner-validated opaque cookie for the pinned `Plugin_unzSetPassword` name. Streams expire at filesystem barriers; immutable `ReadFile` bytes survive cancellation until `FreeFile` or final unload after all pins. File limits and lifecycle details are in `docs/plugin-filesystem.md`.

The public `Plugin_Tcp*` and `Plugin_Tcp*MT` APIs retain four numbered sockets per plugin. `Connect` runs only in pinned work and returns success after a real connection, with one absolute five-second DNS/connect deadline. `GetData` and `SendData` use nonblocking partial byte counts, at most 64 KiB per call; zero means busy/would-block and minus one means closed/invalid. MT plugin IDs must match the caller's pinned module. Close/cancellation schedules retirement outside the tick. Cancel may race a previously validated nonblocking call that returns its actual in-flight bytes; it never admits a new old-generation operation. Backend shutdown requires every pinned caller to finish.

`scripts/plugin_io_native_probe.py` launches only its isolated dedicated server and loopback listeners for at most 30 seconds, packages independently verified stored/deflated/classic-encrypted ZIP entries, runs `khz_fixture_files_start/report` and `khz_fixture_tcp_start/report`, then unloads and checks bounded storage drains. It preserves exact native/binary/source evidence and cleans only its newly owned files/processes. Its existence and standalone test passes do not prove native integration; run it only after a coherent build has been deployed.
